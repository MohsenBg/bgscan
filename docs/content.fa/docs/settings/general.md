# تنظیمات عمومی

> 💡 **نکته:** لازم نیست فایل TOML را دستی ویرایش کنید. از منوی اصلی به **Settings → General Settings** بروید تا این گزینه‌ها را داخل برنامه تغییر دهید.

فایل تنظیمات: `settings/general_settings.toml`

این فایل محدودیت‌های کلی اسکن، حالت اجرای Pipeline و اندازهٔ بافرها را کنترل می‌کند.

## خلاصهٔ گزینه‌ها

| گزینه | پیش‌فرض | توضیح |
|---|---:|---|
| `status_interval` | `1000` | فاصلهٔ به‌روزرسانی پیشرفت، میلی‌ثانیه |
| `stop_after_found` | `0` | رزرو شده؛ موتور فعلی آن را اجرا نمی‌کند |
| `max_ips_to_test` | `0` | سقف IPهایی که از ورودی خوانده می‌شوند |
| `pipeline_mode` | `"streaming"` | حالت اجرای اسکن چندمرحله‌ای |
| `max_ips_per_stage` | `100000` | اندازهٔ بافر کانال بین مرحله‌ها |
| `batch_size` | `1000` | اندازهٔ Batch در حالت Batch |
| `shuffled` | `true` | تصادفی‌کردن ترتیب هدف‌ها |

## Status Interval

```toml
status_interval = 1000
```

هر مرحله هر چند میلی‌ثانیه یک‌بار وضعیت پیشرفت را به رابط کاربری می‌فرستد. محدودهٔ مجاز ۱۰۰ میلی‌ثانیه تا ۶۰ ثانیه است. مقدار کمتر، نمایش نرم‌تری می‌دهد ولی در اسکن‌های بزرگ CPU بیشتری مصرف می‌کند.

## Stop After Found

```toml
stop_after_found = 0
```

برای توقف اسکن بعد از N نتیجهٔ موفق در نظر گرفته شده، اما موتور فعلی هنوز از آن استفاده نمی‌کند. روی `0` بگذارید.

## Max IPs to Test

```toml
max_ips_to_test = 0
```

سقف تعداد IPهایی است که از منبع ورودی خوانده می‌شوند. `0` یعنی همهٔ IPها خوانده شوند. برای نمونه‌برداری از فهرست بزرگ یا محدودهٔ بزرگ IPv6 کاربرد دارد.

## Pipeline Mode

```toml
pipeline_mode = "streaming"
```

مشخص می‌کند هدف‌ها در اسکن چندمرحله‌ای چطور بین مرحله‌ها حرکت کنند:

| مقدار | رفتار |
|---|---|
| `streaming` یا `parallel` | همهٔ مرحله‌ها هم‌زمان اجرا می‌شوند و IPهای موفق از طریق کانال حافظه به مرحلهٔ بعد می‌روند. |
| `sequential` یا `simple` | مرحلهٔ اول تمام می‌شود و نتیجه‌اش را می‌نویسد؛ مرحلهٔ بعد همان فایل را ورودی می‌گیرد. |
| `batch` یا `pipeline` | IPها تکه‌تکه خوانده می‌شوند و هر تکه از همهٔ مرحله‌ها عبور می‌کند. |

مقدار خالی یا ناشناخته هنگام خواندن به `sequential` برمی‌گردد، اما اعتبارسنجی فقط مقدارهای جدول را قبول می‌کند و در صورت خطا پیش‌فرض را برمی‌گرداند. برای تفاوت حالت‌ها [زنجیرهٔ اسکن](../scanner/scan-pipeline.md) را ببینید.

## Max IPs Per Stage

```toml
max_ips_per_stage = 100000
```

اندازهٔ کانالی است که یک مرحلهٔ Streaming را به مرحلهٔ بعد وصل می‌کند. بافر بزرگ‌تر باعث می‌شود مرحلهٔ سریع کمتر منتظر مرحلهٔ کند بماند، اما حافظهٔ بیشتری مصرف می‌کند. هر ورودی بافر فقط یک آدرس است.

اگر تعداد Workerهای مرحلهٔ بعد بیشتر باشد، این مقدار تا همان تعداد بالا می‌رود. فقط در حالت `streaming` استفاده می‌شود و محدودهٔ مجاز آن ۱ تا ۱۰٬۰۰۰٬۰۰۰ است.

## Batch Size

```toml
batch_size = 5000
```

تعداد IP در هر تکه در حالت `batch` است. در اسکن چندمرحله‌ای، اندازهٔ واقعی `max(batch_size, بیشترین تعداد Worker بعد از مرحلهٔ اول)` خواهد بود تا Batch از Workerهایی که باید آن را خالی کنند کوچک‌تر نباشد.

## Shuffle Targets

```toml
shuffled = false
```

ترتیب IPها را قبل از اسکن تصادفی می‌کند. برای پخش‌کردن فشار بین Subnetها، فشار نیاوردن به یک محدوده و گرفتن نمونهٔ بهتر همراه `max_ips_to_test` مفید است.
