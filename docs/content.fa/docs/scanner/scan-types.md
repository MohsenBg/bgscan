# انواع اسکن

توی منوی نوع اسکن، شش گزینه دارید که هر کدوم با یه کلید انتخاب می‌شن:

| کلید | نوع اسکن | چه کاری انجام می‌ده | فایل تنظیمات |
|-----|-----------|--------------|--------------------|
| `i` | اسکن ICMP | درخواست اکو می‌فرسته و زمان رفت‌وبرگشت رو اندازه می‌گیره | [`icmp_settings.toml`](../settings/icmp.md) |
| `t` | اسکن TCP | به یه پورت وصل می‌شه و تأخیر Handshake رو اندازه می‌گیره | [`tcp_settings.toml`](../settings/tcp.md) |
| `h` | اسکن HTTP | درخواست HTTP می‌فرسته و وضعیت پاسخ، نسخه و TLS رو ثبت می‌کنه | [`http_settings.toml`](../settings/http.md) |
| `x` | اسکن Xray | ترافیک رو از یه Outbound عبور می‌ده و اتصال رو می‌سنجه | [`xray_settings.toml`](../settings/xray.md) |
| `r` | ریزالور DNS | هر IP رو به‌عنوان ریزالور تست می‌کنه و در صورت نیاز، هجکینگ DPI رو بررسی می‌کنه | [`dns_settings.toml`](../settings/dns.md) |
| `d` | تونل DNS | بررسی می‌کنه کدوم ریزالورها می‌تونن تونل DNS رو عبور بدن | [`dns_settings.toml`](../settings/dns.md) |

**ریزالور DNS** یه اسکن مستقله. هر IP هدف رو به‌عنوان ریزالور بررسی می‌کنه و در صورت فعال بودن گزینه مربوطه، هجکینگ DPI رو هم تشخیص می‌ده.

**تونل DNS** اول مرورگر Config رو باز می‌کنه تا یکی از Configهای ذخیره‌شده رو انتخاب کنید: DNSTT، VayDNS، Slipstream، MasterDNS، StormDNS یا TheFeed. اگه گزینه `check_dns_resolver` توی تنظیمات تونل DNS فعال باشه، قبل از شروع تونل یه پیش‌اسکن ریزالور هم اجرا می‌شه.

**اسکن Xray** ابتدا ازتون می‌خواد قالب Outbound رو انتخاب کنید. اگه `pre_scan_type` روی `icmp`، `tcp` یا `http` باشه، همون اسکن قبل از Xray اجرا می‌شه و هدف‌ها رو فیلتر می‌کنه. با انتخاب `none`، اسکن Xray بدون پیش‌اسکن شروع می‌شه.

## ICMP

این پروب درخواست اکو می‌فرسته و منتظر جواب می‌مونه. از یه سوکت مشترک IPv4 بین Workerها استفاده می‌کنه و اگه سیستم اجازه بده، یه سوکت مشترک IPv6 هم داره. جواب هر درخواست به همون Workerی برمی‌گرده که درخواست رو فرستاده.

تأخیر، تعداد تلاش‌ها و نوع سوکت رو ثبت می‌کنه. سوکت می‌تونه raw باشه یا در صورت نداشتن دسترسی لازم، از UDP استفاده کنه.

ICMP راه کم‌هزینه‌ای برای محدود کردن یه رنج بزرگ از IPها قبل از اجرای اسکن‌های سنگین‌تره.

## TCP

اسکن TCP از نوع Connect کامل انجام می‌شه، نه SYN. یعنی اتصال به پورت تنظیم‌شده رو تا پایان Handshake پیش می‌بره و تأخیر اولین تلاش موفق رو ثبت می‌کنه.

اگه اتصال Timeout بشه، تا رسیدن به سقف `tries` دوباره تلاش می‌کنه. اما اگه اتصال با خطای refused رد بشه، همون لحظه شکست می‌خوره تا بررسی IPهای غیرفعال سریع‌تر تموم بشه.

نتیجه شامل تأخیر، پورت و تعداد تلاش‌هاست.

## HTTP

برای هر هدف، یه درخواست با یکی از نسخه‌های HTTP/1.1، HTTP/2 یا HTTP/3 می‌فرسته. انتخاب بین `h1` و `h2` با استفاده از ALPN انجام می‌شه، اما `h3` پروب جداگانه‌ای داره که از QUIC استفاده می‌کنه.

پاسخ‌هایی که کد وضعیتشون توی `accepted_status_codes` نباشه، پذیرفته نمی‌شن. اگه این فهرست خالی باشه، همه کدهای وضعیت قابل قبول‌اند.

نتیجه شامل تأخیر، کد وضعیت، نسخه HTTP انتخاب‌شده و استفاده شدن یا نشدن TLS می‌شه.

## Xray

برای هر هدف، یه نمونه Xray با قالب Outbound انتخاب‌شده اجرا می‌شه. بعد تأخیر اتصال از طریق پروکسی محلی اندازه‌گیری می‌شه.

بسته به مقدار `connectivity_test_type`، تست دانلود، آپلود یا هر دو هم اجرا می‌شن. اگه سرعت از حداقل مقدار تنظیم‌شده کمتر باشه، اون هدف رد می‌شه.

نتیجه شامل تأخیر و سرعت دانلود و آپلود می‌شه. اگه فقط اتصال بررسی بشه، مقدار هر دو سرعت صفر می‌مونه.

## ریزالور DNS

توی این اسکن، هر IP هدف به‌عنوان یه ریزالور DNS بررسی می‌شه. اگه `check_dpi` فعال باشه، پروب اول یه نام تصادفی زیر دامنه `.invalid` رو درخواست می‌کنه. اگه ریزالور برای این نام نامعتبر جواب موفق برگردونه، یعنی احتمالاً داره جواب DNS رو دست‌کاری می‌کنه. در نتیجه اون ریزالور از ادامه اسکن کنار گذاشته می‌شه.

بعد از این مرحله، پروب از ریزالورهای باقی‌مونده درباره نوع‌های Record تنظیم‌شده سؤال می‌کنه. اگه یکی از درخواست‌ها کد پاسخ قابل قبول بگیره، ریزالور پذیرفته می‌شه.

نتیجه شامل تأخیر، نوع Record پاسخ‌داده‌شده، تعداد تلاش‌ها، کد پاسخ و وضعیت اجرای بررسی DPI می‌شه.

## تونل DNS

این اسکن بررسی می‌کنه کدوم ریزالورها می‌تونن ترافیک یه تونل DNS رو عبور بدن. اول باید یکی از Configهای ذخیره‌شده رو از مرورگر Config انتخاب کنید.

هر شش پروتکل زیر قابل اسکن‌اند:

- **DNSTT:** تونل DNS با استفاده از کتابخانه VayDNS و فریمینگ سازگار با نسخه قدیمی DNSTT
- **VayDNS:** پروتکل بومی VayDNS با تنظیمات QNAME، MTU و نوع Record
- **Slipstream:** کلاینت تونل داخلی `libslipstream-client` با تنظیمات مربوط به رزولوشن DNS و کنترل ازدحام
- **TheFeed:** تونل رمزنگاری‌شده روی UDP، TCP یا DNS با TLS و کدگذاری تک‌کوئری یا دوتایی
- **MasterDNS:** تونل داخلی با رمزنگاری قابل تنظیم و قابلیت کشف MTU
- **StormDNS:** تونل داخلی با رمزنگاری قابل تنظیم، کشف MTU و امکان انتخاب نوع کوئری

Slipstream، MasterDNS و StormDNS برای هر هدف، کلاینت تونل خودشون رو اجرا می‌کنن و روی یه پورت SOCKS5 محلی گوش می‌دن. به همین دلیل، اسکنشون خیلی کندتر از مرحله بررسی ریزالوره.

DNSTT و VayDNS اتصال رو از طریق خود تونل اعتبارسنجی می‌کنن. در همه این پروتکل‌ها، تأخیر بعد از برقراری تونل اندازه‌گیری می‌شه، نه مدت‌زمانی که برای راه‌اندازی تونل لازم بوده.

اگه `check_dns_resolver` فعال باشه، قبل از اجرای تونل یه پیش‌اسکن ریزالور انجام می‌شه و فقط هدف‌های فعال به مرحله تونل می‌رسن. گزینه `adaptive_resolver` هم تنظیمات ریزالور رو بر اساس ترنسپورت، پورت و دامنه موجود در Config تونل هماهنگ می‌کنه.

برای جزئیات تنظیمات هر پروتکل، صفحه [تونل DNS](../dns-tunneling/) رو ببینید.
