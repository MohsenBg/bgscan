# تنظیمات Xray

> 💡 **نکته:** لازم نیست فایل TOML رو دستی ویرایش کنید. می‌تونید تنظیمات رو مستقیماً از داخل خود BGScan تغییر بدید.
>
> از منوی اصلی وارد **Settings → Xray Settings** بشید و گزینه‌ها رو با Inspector داخل TUI تنظیم کنید.

فایل تنظیمات: `settings/xray_settings.toml`

این فایل تنظیمات تست اتصال و سرعت Outboundهای Xray رو مشخص می‌کنه. BGScan با استفاده از این ماژول، دسترسی به سرورهای مقصد و در صورت نیاز، سرعت دانلود و آپلود رو بررسی می‌کنه.

## مرجع سریع

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| `timeout` | وابسته به پلتفرم | حداکثر زمان انتظار برای تکمیل تست اتصال Xray، به میلی‌ثانیه |
| `speed_test_timeout` | وابسته به پلتفرم | حداکثر زمان هر تست سرعت دانلود یا آپلود، به میلی‌ثانیه |
| `workers` | وابسته به پلتفرم | تعداد Workerهای هم‌زمان برای تست اتصال Xray |
| `connectivity_test_type` | `3` | نوع تست: `0` فقط اتصال، `1` فقط دانلود، `2` فقط آپلود، `3` دانلود و آپلود |
| `download_speed` | وابسته به پلتفرم | حداقل سرعت دانلود قابل قبول، برحسب Kbps |
| `upload_speed` | وابسته به پلتفرم | حداقل سرعت آپلود قابل قبول، برحسب Kbps |
| `output_prefix` | `"xray_"` | پیشوند نام فایل‌های خروجی این ماژول |
| `pre_scan_type` | `"tcp"` | نوع بررسی اولیه پیش از Xray: `none`، `icmp`، `tcp` یا `http` |
| `max_concurrent_dials` | وابسته به پلتفرم | حداکثر تعداد Dialهای خروجی هم‌زمان در کل پروسه، مقدار `0` یعنی بدون محدودیت |
| `dial_max_attempts` | وابسته به پلتفرم | حداکثر تعداد تلاش برای Dial در هر ارسال Outbound |

## Timeout تست اتصال

```toml
timeout = 6000
```

حداکثر زمانی که تست اتصال Xray برای تکمیل شدن فرصت داره، برحسب میلی‌ثانیه. اگه تست در این مدت تموم نشه، ناموفق در نظر گرفته می‌شه.

**مقدارهای پیشنهادی:**

- `3000-6000` برای شبکه‌های پایدار
- `6000-12000` برای شبکه‌های دور یا ناپایدار

## Timeout تست سرعت

```toml
speed_test_timeout = 6000
```

حداکثر زمان هر تست دانلود یا آپلود رو برحسب میلی‌ثانیه مشخص می‌کنه.

مقدار داده‌ای که در تست جابه‌جا می‌شه، بر اساس این زمان و حداقل سرعت تعیین می‌شه. برای دانلود، محاسبه به این صورته:

`(speed_test_timeout / 1000) × download_speed`

برای آپلود هم از `upload_speed` استفاده می‌شه. مقدار به‌دست‌اومده برحسب کیلوبیت هست و برای محاسبه حجم داده به بایت تبدیل می‌شه. به این ترتیب، تست به‌اندازه‌ای داده جابه‌جا می‌کنه که بشه سرعت اتصال رو با حداقل سرعت تعیین‌شده مقایسه کرد.

**مقدارهای پیشنهادی:**

- `3000-8000` برای تست سرعت معمول
- `8000-15000` برای هدف‌هایی با پهنای باند بالا یا شبکه‌های ناپایدار

## Workerها

```toml
workers = 32
```

تعداد Workerهایی رو مشخص می‌کنه که به‌صورت هم‌زمان تست اتصال Xray رو انجام می‌دن. افزایش این مقدار می‌تونه توان تست رو بیشتر کنه، اما مصرف CPU و پهنای باند هم افزایش پیدا می‌کنه.

**مقدارهای پیشنهادی:**

- `8-16` برای سیستم‌هایی با منابع محدود
- `16-32` برای استفاده معمول
- `32-64` برای تست با توان بالاتر

## نوع تست اتصال

```toml
connectivity_test_type = 0
```

مشخص می‌کنه که BGScan چه نوع تستی روی Outbound انجام بده.

مقدارهای پشتیبانی‌شده:

| مقدار | نوع تست | توضیح |
|---|---|---|
| `0` | فقط اتصال | بررسی می‌کنه اتصال برقرار می‌شه یا نه |
| `1` | فقط دانلود | فقط سرعت دانلود بررسی می‌شه |
| `2` | فقط آپلود | فقط سرعت آپلود بررسی می‌شه |
| `3` | دانلود و آپلود | هر دو تست سرعت اجرا می‌شن |

## حداقل سرعت دانلود

```toml
download_speed = 100
```

حداقل سرعت دانلود قابل قبول رو برحسب Kbps مشخص می‌کنه. پروب با توجه به `speed_test_timeout` و این مقدار، حجم داده موردنیاز برای تست رو تعیین می‌کنه. اگه سرعت اندازه‌گیری‌شده کمتر از حد تعیین‌شده باشه، هدف رد می‌شه.

این گزینه فقط وقتی استفاده می‌شه که `connectivity_test_type` برابر `1` یا `3` باشه.

**مقدارهای پیشنهادی:**

- `50-200` برای تست پهنای باند متوسط
- `200-1000` برای تست پهنای باند بالا

## حداقل سرعت آپلود

```toml
upload_speed = 50
```

حداقل سرعت آپلود قابل قبول رو برحسب Kbps مشخص می‌کنه. این گزینه هم مثل `download_speed` عمل می‌کنه و فقط وقتی اعمال می‌شه که `connectivity_test_type` برابر `2` یا `3` باشه.

**مقدارهای پیشنهادی:**

- `25-100` برای تست پهنای باند متوسط
- `100-500` برای تست پهنای باند بالا

## پیشوند خروجی

```toml
output_prefix = "xray_"
```

پیشوند نام تمام فایل‌های خروجی این ماژول رو مشخص می‌کنه. با تغییر این مقدار می‌تونید نتیجه اسکن‌هایی رو که با هدف‌ها یا تنظیمات متفاوت اجرا می‌شن، از هم جدا کنید.

## نوع پیش‌اسکن

```toml
pre_scan_type = "none"
```

مشخص می‌کنه قبل از اجرای تست Xray، یک بررسی اولیه برای دسترسی به هدف انجام بشه یا نه.

اگه هدف در این مرحله رد بشه، دیگه به مرحله Xray نمی‌رسه.

مقدارهای قابل استفاده:

- `none`: بدون پیش‌اسکن. تست Xray مستقیماً اجرا می‌شه.
- `icmp`: بررسی دسترسی با ICMP، با استفاده از تنظیمات ICMP.
- `tcp`: بررسی اتصال TCP به پورت هدف، با استفاده از تنظیمات TCP.
- `http`: بررسی دسترسی از طریق HTTP یا HTTPS، با استفاده از تنظیمات HTTP.

## حداکثر تعداد Dialهای هم‌زمان

```toml
max_concurrent_dials = 128
```

حداکثر تعداد Dialهای خروجی‌ای رو مشخص می‌کنه که می‌تونن در کل پروسه به‌صورت هم‌زمان اجرا بشن. این محدودیت بین تمام Workerها مشترکه.

مقدار `0` یعنی محدودیتی برای تعداد Dialهای هم‌زمان تعیین نشده.

اگه هنگام اسکن‌های بزرگ با تمام شدن سوکت‌ها یا File Descriptorها مواجه می‌شید، می‌تونید این مقدار رو کاهش بدید تا تعداد اتصال‌های هم‌زمان محدود بشه.

محدوده مجاز: `0` تا `10000`.

## حداکثر تلاش برای Dial

```toml
dial_max_attempts = 3
```

تعداد دفعاتی رو مشخص می‌کنه که هر ارسال Outbound برای برقراری اتصال تلاش می‌کنه، پیش از اینکه از ادامه تلاش صرف‌نظر کنه.

محدوده مجاز: `1` تا `10`.
