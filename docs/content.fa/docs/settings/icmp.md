# تنظیمات ICMP

> 💡 **نکته:** از **Settings → ICMP Settings** هم می‌توانید این گزینه‌ها را تغییر دهید.

فایل تنظیمات: `settings/icmp_settings.toml`

پروب ICMP درخواست Echo می‌فرستد و زمان رفت‌وبرگشت را ثبت می‌کند. یک Socket مشترک IPv4 و در صورت پشتیبانی سیستم یک Socket مشترک IPv6 باز می‌کند و پاسخ‌ها را به Worker منتظر می‌رساند.

## خلاصهٔ گزینه‌ها

| گزینه | پیش‌فرض | محدوده | توضیح |
|---|---:|---|---|
| `timeout` | وابسته به سیستم | 100-30000 | زمان انتظار پاسخ Echo، میلی‌ثانیه |
| `tries` | `1` | 1-10 | تعداد درخواست Echo برای هر هدف |
| `workers` | وابسته به سیستم | 1-5000 | تعداد پروب هم‌زمان |
| `output_prefix` | `"icmp_"` | | پیشوند فایل نتیجه |

## Timeout

```toml
timeout = 2000
```

مدت انتظار برای پاسخ هر درخواست Echo بر حسب میلی‌ثانیه است. برای هر تلاش جداگانه حساب می‌شود، پس بدترین زمان برای هر هدف `timeout * tries` است.

- `1500-2000` روی سرور و دسکتاپ
- `2500-3000` روی اندروید

## Retries

```toml
tries = 1
```

تعداد درخواست Echo قبل از این‌که هدف غیرقابل‌دسترسی حساب شود. شمارهٔ تلاشی که پاسخ داده داخل نتیجه ذخیره می‌شود.

## Workers

```toml
workers = 200
```

تعداد هدف‌هایی که هم‌زمان بررسی می‌شوند. Workerها Socket مشترک دارند، پس افزایش مقدار بیشتر نرخ ارسال Packet را بالا می‌برد تا تعداد File Descriptor را. مقدار خیلی بالا ممکن است باعث Rate Limit در Routerهای مسیر شود.

- `15-100` روی اندروید
- `30-400` روی دسکتاپ
- `100-1000` روی سرور

## Output Prefix

```toml
output_prefix = "icmp_"
```

پیشوند نام فایل‌های نتیجهٔ این پروب است. فایل‌ها داخل `result/icmp/` ذخیره می‌شوند.

## حالت Socket

برای این مورد تنظیمی وجود ندارد، ولی داخل نتیجه ثبت می‌شود. پروب اول تلاش می‌کند Socket خام ICMP باز کند. اگر برنامه دسترسی لازم نداشته باشد، از Socket بدون نیاز به دسترسی ویژهٔ UDP (datagram) استفاده می‌کند. حالت واقعی هر نتیجه `raw` یا `udp` ثبت می‌شود.

پشتیبانی IPv6 به‌صورت best effort است. اگر Socket IPv6 باز نشود، اسکن IPv4 همچنان کار می‌کند ولی هدف‌های IPv6 با خطا مواجه می‌شوند.
