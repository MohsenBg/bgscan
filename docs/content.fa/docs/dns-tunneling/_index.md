# تونل DNS

BGScan بررسی می‌کنه کدوم ریزالورهای DNS می‌تونن ترافیک یک تونل رو عبور بدن. در حال حاضر، شش پروتکل پشتیبانی می‌شه که هرکدوم تنظیمات اختصاصی خودشون رو دارن. این تنظیمات در فایل‌های TOML جداگانه‌ای زیر پوشه `assets/dns-tunneling/` ذخیره می‌شن.

برای ساخت و مدیریت Configهای تونل، از منوی اصلی وارد **Main Menu → DNS Tunneling** بشید.

## پروتکل‌ها

| پروتکل | توضیح | نیازمندی‌ها |
| --- | --- | --- |
| [**DNSTT**](./dnstt/) | تونل DNS با استفاده از کتابخانه VayDNS و فریمینگ سازگار با DNSTT | دامنه، کلید عمومی |
| [**VayDNS**](./vaydns/) | پروتکل بومی VayDNS با قابلیت تنظیم QNAME، MTU و نوع رکورد | دامنه، کلید عمومی |
| [**Slipstream**](./slipstream/) | کلاینت تونل داخلی که کتابخانه `libslipstream-client` رو بارگذاری می‌کنه | دامنه، کتابخانه Slipstream |
| [**MasterDNS**](./masterdns/) | تونل داخلی با رمزنگاری قابل تنظیم و قابلیت کشف MTU | دامنه، کلید رمزنگاری |
| [**StormDNS**](./stormdns/) | تونل داخلی با رمزنگاری، کشف MTU و امکان انتخاب نوع کوئری | دامنه، کلید رمزنگاری |
| [**TheFeed**](./thefeed/) | تونل رمزنگاری‌شده روی UDP، TCP یا DNS با TLS | دامنه، عبارت عبور یا Passphrase |

هر شش پروتکل داخل خود BGScan اجرا می‌شن. Slipstream از کتابخانه کلاینت خودش استفاده می‌کنه که با `purego` بارگذاری می‌شه. بقیه هم از کتابخانه‌های داخلی Go استفاده می‌کنن.

Slipstream، MasterDNS و StormDNS برای هر پروب یک شنونده محلی SOCKS5 راه‌اندازی می‌کنن.

DNSTT، VayDNS و Slipstream از مسیریابی اختیاری ترافیک از طریق پروکسی SOCKS5 یا SSH پشتیبانی می‌کنن. احراز هویت این پروکسی‌ها می‌تونه با Password یا Key انجام بشه. Configهای MasterDNS، StormDNS و TheFeed تنظیمات پروکسی ندارن.

برای هر اسکن باید یک Config ذخیره‌شده انتخاب کنید. BGScan بر اساس پروتکل انتخاب‌شده، مرحله اسکن مربوط به اون رو می‌سازه. در صورت فعال بودن گزینه مربوطه، قبل از تست تونل یک پیش‌اسکن ریزالور هم اجرا می‌شه.

## نحوه کار

اگه گزینه `check_dns_resolver` فعال باشه، اسکن تونل DNS در دو مرحله انجام می‌شه:

1. **پیش‌اسکن ریزالور:** هر IP هدف به‌عنوان یک ریزالور DNS بررسی می‌شه. فقط ریزالورهایی که به کوئری‌های پایه DNS پاسخ بدن و در صورت فعال بودن بررسی DPI، از اون هم عبور کنن، به مرحله بعد می‌رن.
2. **تست تونل:** هر ریزالور باقی‌مونده بررسی می‌شه تا مشخص بشه می‌تونه ترافیک یک اتصال تونل رو عبور بده یا نه. پروب، تونل رو با پروتکل انتخاب‌شده راه‌اندازی می‌کنه و عبور ترافیک از اون رو بررسی می‌کنه.

اگه `adaptive_resolver` فعال باشه، تنظیمات پیش‌اسکن ریزالور به‌صورت خودکار با ترنسپورت، پورت و دامنه Config تونل هماهنگ می‌شن. به این ترتیب، پیش‌اسکن همون مسیری رو بررسی می‌کنه که تونل قراره ازش استفاده کنه.

تأخیری که در نتیجه گزارش می‌شه، بعد از برقراری تونل اندازه‌گیری می‌شه. بنابراین، زمان صرف‌شده برای راه‌اندازی تونل در این مقدار محاسبه نمی‌شه.

## مدیریت Configها

جدول بخش **Main Menu → DNS Tunneling** همه Configهای ذخیره‌شده رو نشون می‌ده.

| ستون | توضیح |
| --- | --- |
| Name | نام Config |
| Protocol | نوع پروتکل: DNSTT، VayDNS، Slipstream، MasterDNS، StormDNS یا TheFeed |
| Auth | خلاصه اطلاعات پروکسی و احراز هویت برای DNSTT، VayDNS و Slipstream، یا برچسب رمزنگاری و Passphrase برای بقیه پروتکل‌ها |
| Created Time | زمان ساخت فایل |

کلیدهای قابل استفاده:

| کلید | عملکرد |
| --- | --- |
| `a` | ساخت Config جدید و باز کردن انتخاب‌گر پروتکل |
| `r` | تغییر نام Config انتخاب‌شده |
| `x` | حذف Config انتخاب‌شده |
| `Enter` | ویرایش Config انتخاب‌شده |

## محل ذخیره Configها

Configهای تونل در فایل‌های TOML و پوشه مربوط به هر پروتکل ذخیره می‌شن:

```text
assets/dns-tunneling/
├── dnstt/
│   └── <config-name>.toml
├── vaydns/
│   └── <config-name>.toml
├── slipstream/
│   └── <config-name>.toml
├── masterdns/
│   └── <config-name>.toml
├── stormdns/
│   └── <config-name>.toml
└── thefeed/
    └── <config-name>.toml
```

## تنظیمات پیش‌فرض بر اساس پلتفرم

BGScan تعداد Workerها و Timeout رو با توجه به پلتفرم و سطح منابع سیستم به‌صورت خودکار تنظیم می‌کنه.

**Desktop**

| تنظیم | Low | Mid | High |
| --- | ---: | ---: | ---: |
| Workerهای تونل DNS | 8 | 16 | 32 |
| Timeout تونل DNS | 10s | 10s | 10s |
| Workerهای ریزالور DNS | 30 | 80 | 100 |

| تنظیم | Low | Mid | High |

| Timeout تونل DNS | 10s | 10s | 10s |
