# تنظیمات Writer نتیجه

> 💡 **نکته:** لازم نیست فایل TOML رو دستی ویرایش کنید. می‌تونید این تنظیمات رو مستقیماً از داخل BGScan تغییر بدید.
>
> از منوی اصلی وارد **Settings → General Settings** بشید، تب **Writer** رو باز کنید و گزینه‌ها رو با Inspector داخل TUI تغییر بدید.

فایل تنظیمات: `settings/writer_settings.toml`

این بخش تنظیمات مربوط به بافر نتیجه‌ها، زمان Flush و پوشه‌ای رو مشخص می‌کنه که فایل‌های نتیجه در اون ذخیره می‌شن.

هر مرحله اسکن Writer مخصوص خودش رو داره. Workerها نتیجه‌ها رو از طریق یک کانال به Writer می‌فرستن. Writer نتیجه‌ها رو در یک Batch جمع می‌کنه و هنگام هر Flush، اون‌ها رو با فایل CSV مربوط به همون مرحله Merge Sort می‌کنه.

## مرجع سریع

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| `merge_flush_interval` | `2000` | فاصله بین Flushها، به میلی‌ثانیه |
| `chan_size` | وابسته به پلتفرم | ظرفیت کانال بین Workerها و Writer |
| `batch_size` | وابسته به پلتفرم | تعداد نتیجه‌هایی که پیش از Flush در حافظه جمع می‌شن |
| `result_directory` | `"result"` | پوشه اصلی ذخیره فایل‌های نتیجه |
| `ignore_err` | `false` | خطاهای Writer لاگ می‌شن و اسکن به‌جای توقف ادامه پیدا می‌کنه |

## فاصله بین Flushها

```toml id="2f7x9c"
merge_flush_interval = 2000
```

فاصله زمانی بین Flushهای دوره‌ای رو برحسب میلی‌ثانیه مشخص می‌کنه. محدوده مجاز از ۱۰۰ میلی‌ثانیه تا ۵ دقیقه است.

علاوه بر Flush دوره‌ای، وقتی تعداد نتیجه‌ها به `batch_size` برسه هم Flush انجام می‌شه. هنگام توقف Writer هم یک Flush نهایی انجام می‌شه تا نتیجه‌هایی که تا اون لحظه دریافت شدن، از دست نرن.

- **فاصله کمتر:** نتیجه‌ها زودتر روی دیسک نوشته می‌شن، اما فایل CSV دفعات بیشتری بازنویسی و مرتب‌سازی می‌شه.
- **فاصله بیشتر:** تعداد عملیات دیسک کمتر می‌شه، اما نتیجه‌های بیشتری برای مدت طولانی‌تری در حافظه می‌مونن.

## اندازه کانال

```toml id="9g5v2k"
chan_size = 1024
```

ظرفیت کانالی رو مشخص می‌کنه که Workerها نتیجه‌ها رو از طریق اون به Writer می‌فرستن.

وقتی کانال پر بشه، Workerها تا خالی شدن ظرفیت منتظر می‌مونن. اگه نتیجه‌ها سریع‌تر از توان Writer تولید می‌شن، می‌تونید این مقدار رو افزایش بدید.

محدوده مجاز: `1` تا `1000000`.

## اندازه Batch

```toml id="4n8w6j"
batch_size = 4096
```

تعداد نتیجه‌هایی رو مشخص می‌کنه که در حافظه جمع می‌شن تا با رسیدن به این تعداد، Flush انجام بشه.

این مقدار روی ظرفیت اولیه Slice مربوط به Batch و میزان حافظه مورد استفاده برای نگه‌داری نتیجه‌ها هنگام Merge هم تأثیر می‌ذاره.

محدوده مجاز: `1` تا `102400`.

## پوشه ذخیره نتیجه‌ها

```toml id="7m3q5v"
result_directory = "result"
```

پوشه اصلی ذخیره فایل‌های نتیجه رو مشخص می‌کنه. مسیر این پوشه نسبت به محل باینری BGScan در نظر گرفته می‌شه و برای هر نوع نتیجه، یک زیرپوشه جداگانه ساخته می‌شه:

- `result/icmp/`
- `result/tcp/`
- `result/http/`
- `result/xray/`
- `result/dns_resolver/`
- `result/dnstt/`
- `result/vaydns/`
- `result/slipstream/`
- `result/masterdns/`
- `result/stormdns/`
- `result/thefeed/`

این پوشه‌ها در صورت نیاز به‌صورت خودکار ساخته می‌شن.

**نکته:** مقدار `result_directory` باید فقط نام پوشه باشه، نه یک مسیر کامل.

## نادیده گرفتن خطاهای Writer

```toml id="2n6b8s"
ignore_err = false
```

وقتی فعال باشه، Writer خطاهاش رو لاگ می‌کنه و اسکن به‌جای توقف ادامه پیدا می‌کنه. این شامل خطاهای راه‌اندازی، نوشتن و Flush هم می‌شه.

Batchی که Flushش ناموفق بوده کنار گذاشته می‌شه، بنابراین ممکنه بعضی نتیجه‌ها در فایل خروجی نباشن. اگه ذخیره شدن همه نتیجه‌های موفق مهمه، این گزینه رو غیرفعال نگه دارید.
