# تنظیمات HTTP

> 💡 **نکته:** لازم نیست فایل TOML رو دستی ویرایش کنید. می‌تونید تنظیمات رو مستقیماً از داخل خود BGScan تغییر بدید.
>
> از منوی اصلی وارد **Settings → HTTP Settings** بشید و گزینه‌ها رو با Inspector داخل TUI تنظیم کنید.

فایل تنظیمات: `settings/http_settings.toml`

پروب HTTP برای هر هدف یک درخواست می‌فرسته و کد وضعیت، نسخه HTTP توافق‌شده و استفاده از TLS رو ثبت می‌کنه. HTTP/1.1 و HTTP/2 از TCP استفاده می‌کنن، اما HTTP/3 روی QUIC اجرا می‌شه.

## مرجع سریع

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| `workers` | وابسته به پلتفرم | تعداد درخواست‌های هم‌زمان، از ۱ تا ۱۰۰۰ |
| `host` | `"example.com"` | هاست درخواست، با امکان تعیین مسیر |
| `server_name` | `""` | مقدار جایگزین SNI، در صورت خالی بودن، از `host` استفاده می‌شه |
| `port` | `443` | پورت هدف، از ۱ تا ۶۵۵۳۵ |
| `protocol` | `"https"` | پروتکل اتصال: `http` یا `https` |
| `version` | `"h1,h2"` | نسخه HTTP مورد استفاده |
| `fingerprint` | `""` | Fingerprint مربوط به ClientHello در uTLS، مقدار خالی یعنی استفاده از کتابخانه استاندارد Go |
| `tls_validation` | `true` | بررسی اعتبار گواهی TLS سرور |
| `min_tls_version` | `"tls1.1"` | حداقل نسخه مجاز TLS |
| `max_tls_version` | `"tls1.3"` | حداکثر نسخه مجاز TLS |
| `timeout` | وابسته به پلتفرم | Timeout درخواست به میلی‌ثانیه، از ۱۰۰ تا ۶۰۰۰۰ |
| `accepted_status_codes` | `[]` | کدهای وضعیت قابل قبول، فهرست خالی یعنی همه کدها پذیرفته می‌شن |
| `output_prefix` | `"http_"` | پیشوند نام فایل نتیجه |

## Workerها

```toml
workers = 50
```

تعداد درخواست‌هایی که به‌صورت هم‌زمان اجرا می‌شن. هر Worker در پروب HTTP یک اتصال برقرار می‌کنه و پاسخ رو می‌خونه. به همین دلیل، معمولاً منابع بیشتری از یک Worker در اسکن TCP مصرف می‌کنه.

مقادیر پیشنهادی برای شروع:

- `10-50` برای سیستم‌هایی با منابع محدود
- `50-100` برای استفاده معمول
- `100-200` برای اسکن با توان بالاتر

## هاست

```toml
host = "example.com"
```

هاستی که درخواست HTTP به اون ارسال می‌شه. می‌تونید مسیر هم مشخص کنید. مثلاً `example.com/path`. این مسیر به URL درخواست اضافه می‌شه، اما هدر `Host` فقط شامل نام دامنه خواهد بود.

## پورت

```toml
port = 443
```

پورت مقصد درخواست رو مشخص می‌کنه. پورت‌های معمول عبارت‌اند از:

- `80` برای HTTP
- `443` برای HTTPS

البته می‌تونید هر پورتی رو که سرویس موردنظر روی اون گوش می‌ده تنظیم کنید.

## پروتکل

```toml
protocol = "https"
```

پروتکل اتصال رو مشخص می‌کنه. مقدار این گزینه باید `http` یا `https` باشه. انتخاب `https` باعث می‌شه اتصال از TLS استفاده کنه.

## اعتبارسنجی TLS

```toml
tls_validation = true
```

وقتی این گزینه روی `true` باشه، گواهی TLS سرور باید معتبر و مورد اعتماد سیستم باشه.

با تنظیم `false`، بررسی اعتبار گواهی غیرفعال می‌شه و گواهی‌های منقضی یا خودامضا هم پذیرفته می‌شن.

اگه مستقیماً IPها رو اسکن می‌کنید، ممکنه گواهی سرور با IP مقصد مطابقت نداشته باشه. در این شرایط، در صورت نیاز می‌تونید اعتبارسنجی رو غیرفعال کنید.

## نسخه HTTP

```toml
version = "h1,h2"
```

این گزینه مشخص می‌کنه پروب از کدوم نسخه HTTP استفاده کنه.

| مقدار | معنی |
|---|---|
| `h1` | فقط HTTP/1.1 |
| `h2` | فقط HTTP/2 |
| `h1,h2` | انتخاب نسخه از طریق ALPN |
| `h3` | HTTP/3 روی QUIC |

نام‌های جایگزین زیر هم پذیرفته می‌شن:

- `http1`
- `http1.1`
- `http2`
- `http3`
- `http1,http2`
- `http2,http1`

HTTP/3 از پروب جداگانه‌ای روی QUIC استفاده می‌کنه و همیشه با TLS 1.3 اجرا می‌شه. بنابراین، تنظیمات `min_tls_version` و `max_tls_version` روی اون تأثیری ندارن.

## Timeout

```toml
timeout = 4000
```

حداکثر زمان اختصاص‌یافته به هر درخواست، برحسب میلی‌ثانیه.

برای شروع می‌تونید این محدوده‌ها رو در نظر بگیرید:

- `2000-5000` برای شبکه‌های پایدار
- `5000-10000` برای شبکه‌های دور یا ناپایدار

اگه Timeout خیلی کم باشه، ممکنه اتصال‌های کند به‌عنوان شکست‌خورده ثبت بشن.

## محدوده نسخه TLS

```toml
min_tls_version = "tls1.1"
max_tls_version = "tls1.3"
```

حداقل و حداکثر نسخه TLS قابل استفاده در Handshake رو مشخص می‌کنن.

مقادیر مجاز برای هر دو گزینه عبارت‌اند از:

- `tls1.0`
- `tls1.1`
- `tls1.2`
- `tls1.3`

حداقل نسخه نباید از حداکثر نسخه بیشتر باشه. این تنظیمات برای `version = "h3"` نادیده گرفته می‌شن، چون HTTP/3 همیشه از TLS 1.3 استفاده می‌کنه.

## Fingerprint TLS

```toml
fingerprint = ""
```

این گزینه Fingerprint مربوط به ClientHello رو با استفاده از uTLS مشخص می‌کنه. وقتی مقداری براش تعیین کنید، پروب به‌جای ClientHello پیش‌فرض کتابخانه استاندارد Go، از الگوی انتخاب‌شده استفاده می‌کنه تا مشخصات Handshake به مرورگر موردنظر نزدیک‌تر بشه.

این قابلیت می‌تونه برای بررسی رفتار شبکه‌هایی که بر اساس Fingerprint TLS ترافیک رو شناسایی یا فیلتر می‌کنن، مفید باشه.

نام Fingerprintها به بزرگی و کوچکی حروف حساس نیست.

| دسته | مقادیر قابل استفاده |
|---|---|
| Chrome | `Chrome`، `Chrome_58`، `Chrome_62`، `Chrome_70`، `Chrome_72`، `Chrome_83`، `Chrome_87`، `Chrome_96`، `Chrome_100`، `Chrome_102`، `Chrome_120` |
| Firefox | `Firefox`، `Firefox_55`، `Firefox_56`، `Firefox_63`، `Firefox_65`، `Firefox_99`، `Firefox_102`، `Firefox_105`، `Firefox_120` |
| iOS | `iOS`، `iOS_11_1`، `iOS_12_1`، `iOS_13`، `iOS_14` |
| سایر | `random` |

مقدار خالی، یعنی پیش‌فرض، از ClientHello استاندارد `crypto/tls` در Go استفاده می‌کنه.

پروب HTTP/3 روی QUIC از uTLS استفاده نمی‌کنه. بنابراین، وقتی `version = "h3"` باشه، Fingerprint انتخاب‌شده اعمال نمی‌شه.

## Server Name Indication یا SNI

```toml
server_name = ""
```

این گزینه مقدار SNI رو مشخص می‌کنه که هنگام Handshake TLS ارسال می‌شه.

اگه مقدارش خالی باشه، نام دامنه از `host` گرفته می‌شه. اگه بخواید IP مشخصی رو با یک نام دامنه خاص تست کنید یا رفتار Domain Fronting رو بررسی کنید، می‌تونید مقدار SNI رو جداگانه تنظیم کنید.

## کدهای وضعیت قابل قبول

```toml
accepted_status_codes = []
```

فهرست کدهای وضعیت HTTP رو مشخص می‌کنه که نتیجه موفق حساب می‌شن.

اگه فهرست خالی باشه یا همه کدهای وضعیت رو پوشش بده، فیلتر غیرفعال می‌شه و هر کد وضعیتی که سرور برگردونه پذیرفته می‌شه.

برای مثال، اگه فقط می‌خواید پاسخ‌های مشخصی پذیرفته بشن، می‌تونید این‌طور تنظیم کنید:

```toml
accepted_status_codes = [200, 204, 301, 302, 307, 308]
```

پاسخ‌هایی که کد وضعیتشون در فهرست نباشه، موفق در نظر گرفته نمی‌شن و به مرحله بعد اسکن چندمرحله‌ای نمی‌رسن.

## پیشوند خروجی

```toml
output_prefix = "http_"
```

پیشوند نام فایل‌های نتیجه‌ای رو مشخص می‌کنه که این پروب تولید می‌کنه. فایل‌ها در مسیر `result/http/` ذخیره می‌شن.
