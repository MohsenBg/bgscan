# فایل‌های نتیجه

بعد از تموم شدن اسکن، BGScan آدرس‌های موفق و اطلاعاتی رو که اندازه گرفته، توی فایل نتیجه ذخیره می‌کنه. فایل‌ها بر اساس نوع اسکن توی پوشه‌های جدا قرار می‌گیرن. از داخل TUI هم می‌تونید فایل‌ها رو ببینید، تغییر نام بدید یا حذف کنید.

---

## مشاهده فایل‌های نتیجه

از منوی اصلی وارد **Result Files** بشید یا کلید `r` رو بزنید تا فهرست فایل‌های نتیجه رو ببینید.

جدول، فایل‌هایی رو نشون می‌ده که در Registry نتایج ثبت شدن. فایل‌ها از جدیدترین به قدیمی‌ترین مرتب می‌شن و این اطلاعات رو نمایش می‌دن:

| ستون | توضیح |
|---|---|
| File Name | نام فایل نتیجه، بدون پسوند `.csv` |
| Created Time | زمان آخرین تغییر فایل |
| Type | نوع نتیجه، مثل `ICMP`، `TCP`، `HTTP`، `DNSResolver` و `DNSTT` |
| Size | حجم فایل روی دیسک |

کلیدهای اصلی این بخش:

| کلید | عملکرد |
|---|---|
| `Enter` | باز کردن فایل انتخاب‌شده در IP Viewer |
| `r` | تغییر نام فایل |
| `x` | حذف دائمی فایل |

### کلیدهای جدول

مرورگر فایل‌های نتیجه از همون جدول مشترک برنامه استفاده می‌کنه:

| کلید | عملکرد |
|---|---|
| `↑` / `↓` یا `k` / `j` | حرکت یک ردیف به بالا یا پایین |
| `u` / `d` | حرکت به‌اندازه نصف صفحه |
| `PgUp` / `PgDn` | حرکت یک صفحه به بالا یا پایین |
| `g` / `G` | رفتن به اولین یا آخرین ردیف |
| `s` | تغییر ستون مرتب‌سازی |
| `o` | معکوس کردن ترتیب مرتب‌سازی |
| `/` | فیلتر کردن ردیف‌ها |
| `b` یا `Esc` | برگشت به صفحه قبل |

مرتب‌سازی با توجه به نوع داده هر ستون انجام می‌شه. برای مثال، IPها، زمان‌ها، عددها و متن‌ها هر کدوم به شکل طبیعی خودشون مرتب می‌شن. زمان و پهنای باند هم برای نمایش قالب‌بندی می‌شن، اما مرتب‌سازی بر اساس مقدار واقعی اون‌ها انجام می‌شه.

### باز کردن فایل نتیجه

روی فایل موردنظرتون `Enter` بزنید تا در IP Viewer باز بشه. ستون‌های نمایش‌داده‌شده به نوع نتیجه بستگی دارن. برای مثال، نتیجه‌های ICMP، TCP، HTTP، DNS و تونل اطلاعات مخصوص خودشون رو دارن و نتیجه‌های Xray علاوه بر تأخیر، سرعت دانلود و آپلود رو هم نشون می‌دن.

مقادیر مربوط به زمان و پهنای باند هم بر اساس کیفیتشون رنگ‌بندی می‌شن.

> **محدودیت فعلی:** فایل‌های نتیجه MasterDNS و StormDNS روی دیسک ذخیره می‌شن، اما Schema اون‌ها هنگام شروع برنامه ثبت نمی‌شه. به همین دلیل، این فایل‌ها در مرورگر Result Files نمایش داده نمی‌شن و از همون‌جا قابل باز کردن نیستن. با این حال، می‌تونید CSV اون‌ها رو با ابزارهای دیگه‌ای که از CSV پشتیبانی می‌کنن باز کنید.

## محل ذخیره فایل‌ها

فایل‌های نتیجه در پوشه `result/` کنار فایل اجرایی BGScan ذخیره می‌شن. هر نوع اسکن هم پوشه مخصوص خودش رو داره:

```text
<bgscan-root>/
└── result/
    ├── icmp/
    ├── tcp/
    ├── http/
    ├── xray/
    ├── dns_resolver/
    ├── dnstt/
    ├── vaydns/
    ├── slipstream/
    ├── masterdns/
    ├── stormdns/
    └── thefeed/
```

هر پوشه فایل‌های `.csv` مربوط به همون نوع اسکن رو نگه می‌داره. این پوشه‌ها هنگام اجرای اسکن به‌صورت خودکار ساخته می‌شن و نیازی نیست دستی ایجادشون کنید.

## نام فایل‌های نتیجه

نام هر فایل از پیشوند تعیین‌شده برای نوع اسکن و زمان ایجاد اون ساخته می‌شه:

```text
<prefix><YYYYMMDD_HHMMSS>.csv
```

هر نوع اسکن پیشوند پیش‌فرض خودش رو داره:

| نوع اسکن | پیشوند پیش‌فرض | نمونه نام فایل |
|---|---|---|
| ICMP | `icmp_` | `icmp_20240711_143022.csv` |
| TCP | `tcp_` | `tcp_20240711_143022.csv` |
| HTTP | `http_` | `http_20240711_143022.csv` |
| Xray | `xray_` | `xray_20240711_143022.csv` |
| ریزالور DNS | `dns_` | `dns_20240711_143022.csv` |
| DNSTT | `dns_tun_` | `dns_tun_20240711_143022.csv` |
| VayDNS | `dns_tun_` | `dns_tun_20240711_143022.csv` |
| Slipstream | `dns_tun_` | `dns_tun_20240711_143022.csv` |
| MasterDNS | `dns_tun_` | `dns_tun_20240711_143022.csv` |
| StormDNS | `dns_tun_` | `dns_tun_20240711_143022.csv` |
| TheFeed | `dns_tun_` | `dns_tun_20240711_143022.csv` |

پیشوند هر نوع اسکن رو می‌تونید در فایل تنظیمات مربوط به همون نوع تغییر بدید. برای اطلاعات بیشتر، [نمای کلی تنظیمات](../settings/overview.md) رو ببینید.

## ساختار فایل‌های نتیجه

فایل‌های نتیجه با فرمت CSV ذخیره می‌شن و ردیف عنوان ندارن. هر ردیف شامل اطلاعات یکی از هدف‌هاییه که اسکن اون رو قبول کرده. ساختار هر ردیف به Schema مربوط به نوع اسکن بستگی داره.

همهٔ انواع اسکن حداقل IP هدف و تأخیر رو ذخیره می‌کنن. ستون‌های دیگه بر اساس اطلاعاتی که هر پروب اندازه می‌گیره، متفاوتن.

| نوع اسکن | ستون‌های CSV |
|---|---|
| ICMP | `ip, latency, tries, mode` |
| TCP | `ip, latency, port, tries` |
| HTTP | `ip, latency, status, version, tls` |
| Xray | `ip, latency, download, upload` |
| ریزالور DNS | `ip, latency, record_type, tries, rcode, dpi_check` |
| DNSTT | `ip, latency, transport, port, auth, proxy` |
| VayDNS | `ip, latency, transport, port, auth, proxy` |
| Slipstream | `ip, latency, port, auth, proxy` |
| MasterDNS | `ip, latency, port, enc` |
| StormDNS | `ip, latency, port, query, enc` |
| TheFeed | `ip, latency, domain, mode` |

معنی ستون‌ها:

- `ip`: آدرس IPv4 یا IPv6 هدفی که پاسخ داده.
- `latency`: تأخیر رفت‌وبرگشت یا برقراری اتصال، مثلاً `123ms`.
- `download` / `upload`: سرعت دانلود و آپلود در اسکن Xray. اگه تست مربوطه اجرا نشده باشه، مقدارش `0 bps` می‌شه.
- `status` / `version` / `tls`: کد وضعیت HTTP، نسخه توافق‌شده HTTP و مشخص می‌کنه TLS استفاده شده یا نه.
- `tries`: تعداد تلاش‌ها تا رسیدن به نتیجه موفق.
- `mode`: نوع سوکت ICMP، یعنی `raw` یا `udp`، یا حالت کوئری TheFeed.
- `rcode` / `dpi_check`: کد پاسخ DNS و وضعیت بررسی DPI برای تشخیص پاسخ‌های دست‌کاری‌شده.
- `transport`: نوع ترنسپورت DNS در DNSTT یا VayDNS، مثل `udp`، `tcp` یا `dot`.
- `port`: پورت ریزالور در DNSTT، VayDNS، MasterDNS و StormDNS یا پورت شنونده SOCKS محلی در Slipstream.
- `auth` / `proxy`: روش احراز هویت و نوع پروکسی تنظیم‌شده برای DNSTT، VayDNS یا Slipstream.
- `enc`: شماره روش رمزنگاری در MasterDNS یا StormDNS.
- `query`: نوع کوئری در StormDNS.
- `domain`: دامنه مورد استفاده در TheFeed.

#### نمونه فایل HTTP

```csv
1.2.3.4,45ms,200,HTTP/2.0,true
2606:4700::6810:85e5,120ms,403,HTTP/1.1,true
```

#### نمونه فایل Xray

```csv
1.2.3.4,45ms,0 bps,0 bps
5.6.7.8,120ms,10.00 Mbps,5.00 Mbps
```

در انواع اسکنی که سرعت اندازه‌گیری نمی‌شه، ستون‌های دانلود و آپلود وجود ندارن.

## ترتیب نتیجه‌ها

هدف‌ها در فایل نتیجه بر اساس امتیاز کیفیت مخصوص هر Schema مرتب می‌شن. امتیاز بالاتر یعنی نتیجه بهتر.

هر نوع اسکن متد `Score()` مخصوص خودش رو داره:

- **ICMP، TCP، HTTP، DNS، DNSTT، VayDNS، Slipstream، MasterDNS، StormDNS و TheFeed:** امتیاز بر اساس معکوس تأخیر محاسبه می‌شه، یعنی `1000 / latency_ms`. بنابراین، هدف‌هایی که تأخیر کمتری دارن بالاتر قرار می‌گیرن.
- **Xray:** امتیاز ترکیبی از ۱۰٪ تأخیر، ۶۰٪ سرعت دانلود و ۳۰٪ سرعت آپلود است. اگه یکی از تست‌های سرعت غیرفعال باشه، سهم اون در امتیاز صفر می‌شه. بنابراین، در اسکن Xray که فقط اتصال رو بررسی می‌کنه، ترتیب نتیجه‌ها کاملاً بر اساس تأخیر خواهد بود.

هنگام ذخیره نتیجه‌های جدید، BGScan اون‌ها رو با فایل موجود بر اساس امتیاز و با استفاده از Merge Sort ادغام می‌کنه. اگه یک IP تکراری باشه، رکورد جدیدتر جای قبلی رو می‌گیره. ترتیب مواردی که امتیاز یکسان دارن هم به‌شکل مشخصی تعیین می‌شه تا ادغام‌های تکراری نتیجه یکسانی داشته باشن.
