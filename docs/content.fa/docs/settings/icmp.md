# تنظیمات ICMP

> 💡 **نکته:** لازم نیست فایل TOML رو دستی ویرایش کنید. می‌تونید تنظیمات رو مستقیماً از داخل خود BGScan تغییر بدید.
>
> از منوی اصلی وارد **Settings → ICMP Settings** بشید و گزینه‌ها رو با Inspector داخل TUI تنظیم کنید.

فایل تنظیمات: `settings/icmp_settings.toml`

پروب ICMP برای هر هدف درخواست Echo می‌فرسته و زمان رفت‌وبرگشت پاسخ رو ثبت می‌کنه. برای دریافت پاسخ‌ها، از یک سوکت مشترک IPv4 و در صورت امکان، یک سوکت مشترک IPv6 استفاده می‌کنه. پاسخ‌های دریافتی هم بین Workerهایی که منتظر جواب هستن تقسیم می‌شن.

## مرجع سریع

| تنظیم | پیش‌فرض | محدوده | توضیح |
|---|---|---|---|
| `timeout` | وابسته به پلتفرم | ۱۰۰ تا ۳۰۰۰۰ | حداکثر زمان انتظار برای پاسخ Echo، به میلی‌ثانیه |
| `tries` | `1` | ۱ تا ۱۰ | تعداد درخواست‌های Echo برای هر هدف |
| `workers` | وابسته به پلتفرم | ۱ تا ۵۰۰۰ | تعداد پروب‌های هم‌زمان |
| `output_prefix` | `"icmp_"` | ندارد | پیشوند نام فایل نتیجه |

## Timeout

```toml id="6c7k2a"
timeout = 2000
```

حداکثر زمانی که هر درخواست Echo برای دریافت پاسخ منتظر می‌مونه، برحسب میلی‌ثانیه.

این زمان برای هر تلاش جداگانه محاسبه می‌شه. بنابراین، در بدترین حالت، بررسی یک هدف ممکنه تا `timeout * tries` طول بکشه.

مقادیر پیشنهادی برای شروع:

- `1500-2000` میلی‌ثانیه برای سرور و دسکتاپ
- `2500-3000` میلی‌ثانیه برای دستگاه‌های اندرویدی

## تعداد تلاش

```toml id="k6j4ba"
tries = 1
```

تعداد درخواست‌های Echo که برای هر هدف ارسال می‌شن. اگه هدف در تلاش‌های تعیین‌شده پاسخی نده، غیرقابل‌دسترس در نظر گرفته می‌شه.

شماره تلاشی که پاسخ در اون دریافت شده هم در نتیجه ثبت می‌شه.

## Workerها

```toml id="6fj7uk"
workers = 200
```

تعداد هدف‌هایی که به‌صورت هم‌زمان بررسی می‌شن.

Workerها از سوکت‌های مشترک استفاده می‌کنن. بنابراین، افزایش این مقدار بیشتر روی نرخ ارسال بسته‌ها تأثیر می‌ذاره تا تعداد File Descriptorهای مصرف‌شده. با این حال، مقدار خیلی بالا ممکنه باعث بشه روترهای میانی درخواست‌ها رو محدود کنن یا Rate Limit اعمال کنن.

مقادیر پیشنهادی برای شروع:

- `15-100` برای دستگاه‌های اندرویدی
- `30-400` برای دسکتاپ
- `100-1000` برای سرور

## پیشوند خروجی

```toml id="w4kx3d"
output_prefix = "icmp_"
```

پیشوند نام فایل‌های نتیجه‌ای رو مشخص می‌کنه که این پروب تولید می‌کنه. فایل‌ها در مسیر `result/icmp/` ذخیره می‌شن.

## نوع سوکت

برای انتخاب نوع سوکت تنظیم جداگانه‌ای وجود نداره، اما نوع سوکت استفاده‌شده در نتیجه هر هدف ثبت می‌شه.

پروب ابتدا سعی می‌کنه یک سوکت ICMP از نوع Raw باز کنه. اگه برنامه دسترسی لازم رو نداشته باشه، به سوکت ICMP از نوع Datagram مبتنی بر UDP برمی‌گرده که به دسترسی ویژه نیاز نداره.

نوع سوکت استفاده‌شده در نتیجه با یکی از مقادیر زیر ثبت می‌شه:

- `raw`
- `udp`

پشتیبانی از IPv6 هم به امکانات و مجوزهای سیستم بستگی داره. اگه باز کردن سوکت IPv6 ممکن نباشه، اسکن IPv4 همچنان اجرا می‌شه، اما هدف‌های IPv6 با خطا مواجه می‌شن.
